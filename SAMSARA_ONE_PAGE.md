# Samsāra Travel Platform — One-Page Overview

Samsāra is a full-stack **luxury Destination Management Company (DMC) platform**, built for the PUSL3190 Computing Project. It exists to close a gap that runs through the luxury-travel industry: the journeys being sold are world-class, but the digital experience used to sell and run them is usually not — most DMCs still rely on manual coordination, word-of-mouth referrals, and static brochure websites. Samsāra replaces that with a single connected system where a traveller can be inspired, plan a trip, and submit a booking online, while staff manage the entire operation behind the scenes from live data rather than spreadsheets and phone calls.

The platform is made of **two cooperating applications**. The first is the **public website (`samsara-frontend`)**, a cinematic, content-rich site that travellers use to get inspired and explore curated destinations and experiences. The second is the **Reservation Management System (`samsara-rms`)**, a private back-office where the Samsāra team receives those enquiries and runs the business — clients, reservations, fleet vehicles, guides, suppliers, partners, finance, and email. Both are built with **Next.js 16, React 19, TypeScript, and Tailwind CSS**; the website runs on port 3000 and the RMS on port 3001, and they talk to each other over HTTP.

The signature feature of the website is the **Feelings Engine**, a conversational AI travel consultant grounded in the idea that people travel for feelings, not landmarks. A guest begins by describing how they want to feel — *alive, at peace, adventurous* — and the engine holds a natural, one-question-at-a-time conversation powered by **Anthropic's Claude** model (reached through a secure server-side proxy so the API key is never exposed). With every reply, Claude returns a structured response that quietly fills in a full reservation — traveller details, destinations, transport, accommodation, experiences, and budget — which the page renders on the right as a growing, premium itinerary proposal. Built-in rules add practical intelligence such as sizing a vehicle to the group or flagging date and budget conflicts, and a deterministic offline fallback keeps the conversation working even if the AI is unreachable.

When a guest is ready to book, the **booking flows from the website into the RMS automatically**. The website never touches the database directly; instead it sends the request to its own `/api/bookings` route, which forwards it to the RMS endpoint `/api/bookings/inbound`. The RMS then creates a real reservation in its database with the status *enquiry* and a reference like `SAM-2026-0001`, and triggers two emails — a confirmation to the customer and a notification to staff. From that point the reservation lives in the RMS, where staff move it through a defined **lifecycle** (enquiry through to completed), assign fleet, guides and suppliers, record payments, and rely on an **activity log** that captures every change for a full audit trail.

Underneath, the RMS uses **Supabase** for its database (managed PostgreSQL), authentication, and security. Every request passes through a gatekeeper file (`proxy.ts`) that redirects unauthenticated visitors to the login page and returns clean JSON errors to the API, and access is governed by **role-based permissions** — admin, ops, finance, agent, and partner — so each user only sees what their role allows. The system also generates PDFs for itineraries and confirmations, sends and reads email (including Gmail), and offers dashboards for finance and analytics.

It is worth noting that the project poster describes an **earlier planned stack** — Next.js 14, Node.js with Express, JWT auth, React 18 — whereas the platform was actually built on **Next.js 16 with Supabase**, with the API layer running inside Next.js itself rather than a separate Express server. The poster also lists **OTA (online travel agency) connectivity** as an objective; this remains **future work** and is not yet implemented in the code. Everything else the poster promises — the luxury website, the AI Feelings Engine, the reservation system, the booking hand-off, and the email and audit workflows — is genuinely built and working, making Samsāra a complete demonstration of how a traditionally manual, relationship-driven industry can be turned into a connected, intelligent, and commercially credible digital platform.
